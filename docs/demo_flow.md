# 多工程逐个验证学习路线（按顺序做）

本文件主要说明：如何把你的模块分成多个独立 demo，并按顺序验证。这个思路是：

- 不把所有模块都塞进一个工程
- 不在主板上同时接太多高功耗模块
- 每个模块都单独跑通，降低风险
- 最后再合并工程、统一电源和引脚规划

## 1. 总体思路

你的模块清单中包括：
- AHT21（I2C）
- MPU6050（I2C）
- ESP8266（UART）
- HC‑05（UART）
- HC‑SR04（超声波）
- LCD屏幕（SPI / 8080 / 3-wire）
- OLED屏幕（I2C / SPI）
- PS2 摇杆（模拟/数字）
- RFID（SPI）
- SG90 舵机（PWM）
- WT588F02 语音模块（UART/IO）
- MQ‑2 气体传感器（模拟、加热）
- 土壤湿度模块（模拟）
- 二氧化碳检测模块（根据型号）
- 风扇（直流/控制）
- 迷你 RFID 模块
- 其他模块

这些功能可分成几类：

1. 基础链路：LED、KEY、UART、J‑Link、printf、task
2. 总线通信：I2C、SPI、UART、ADC
3. 传感器：AHT21、MPU6050、MQ‑2、土壤湿度、超声波、CO2 等
4. 交互类：LCD、OLED、摇杆、RFID、舵机
5. 通信类：ESP8266、HC‑05、WT588F02
6. 电源类：18650、TP4056、稳压、升压/降压

## 2. 推荐的拆分路线（按优先级）

### Demo 1：基础工程
目标：
- 验证 MCU 能运行
- 验证 STM32CubeMX 生成代码
- 验证 J‑Link 下载
- 验证 FreeRTOS CMSIS‑V2 任务调度
- 验证串口输出

模块：
- LED
- 按键
- UART（USB-TTL）

### Demo 2：I2C sensor bus
目标：
- 验证 AHT21 温湿度
- 验证 MPU6050 加速度/陀螺仪
- 验证 I2C 总线共用

模块：
- AHT21
- MPU6050
- OLED（可选）

### Demo 3：ADC + DMA + sensor analog
目标：
- 验证 ADC 多通道
- 验证 DMA 连续扫描采样
- 验证模拟输入灵敏度

模块：
- MQ‑2
- 摇杆
- 土壤湿度
- 电池监测

### Demo 4：LCD SPI
目标：
- 验证 ST7789 / LCD 屏幕
- 测试 SPI、GPIO、背光控制、DMA 刷屏

模块：
- LCD屏幕
- 触摸屏（如果有）

### Demo 5：UART communication
目标：
- 验证 ESP8266 AT 命令
- 验证 HC‑05 蓝牙 AT
- 验证串口与外部模块的通信

模块：
- ESP8266
- HC‑05
- WT588F02

### Demo 6：超声波
目标：
- 验证 HC‑SR04 测距原理
- 验证 GPIO 输出和输入捕获 / 定时器测距

### Demo 7：RFID / RC522
目标：
- 验证 SPI 读写 RFID 卡

### Demo 8：舵机 / 风扇 / 语音
目标：
- 验证 PWM 控制舵机
- 验证风扇 PWM 驱动
- 验证语音模块播放

### Demo 9：综合工程（最终封装）
目标：
- 把所有完成验证的模块合并成总工程
- 解决引脚冲突
- 做统一电源方案
- 做分层封装（BSP / Driver / App）

## 3. 每个 demo 的标准流程

每个 demo 都按以下流程：
1. 选择一个独立最小系统板 / 面包板实验区域
2. 从 Demo 模块中选择需要的外设与引脚
3. 在 CubeMX 中生成工程
4. 编译并通过 Keil Debug / J‑Link 下载
5. 按说明接线
6. 观察串口日志和外设行为
7. 如功能正常，则记录在 `notes/` 目录中
8. 若失败，记录错误日志与排查步骤

## 4. 每个 demo 的验收要求

### Demo 1 验收要求
- LED 能按设定频率闪烁
- 按键按下会触发中断并写串口日志
- printf 能正常输出串口消息
- 工程能稳定下载和运行

### Demo 2 验收要求
- AHT21 温度值稳定
- MPU6050 能读取到加速度/角速度寄存器
- I2C 无 NACK 错误

### Demo 3 验收要求
- ADC 值随输入变化而变化
- DMA 采样不丢帧
- 处理任务读取数据稳定

### Demo 4 验收要求
- 屏幕能亮且能显示填充背景或字符
- SPI 初始化无错误
- DMA 传输没有崩溃

### Demo 5 验收要求
- 串口能发 AT 指令
- 返回 OK / 模块信息
- 能在串口读取到模块反馈

### Demo 6 验收要求
- 超声波发射有效
- ECHO 脉冲时间可测量
- 距离结果合理

## 5. 工程开发顺序建议

建议你采用这个顺序：

第一阶段：基础链路
- Demo1：LED + KEY + UART

第二阶段：总线与传感器
- Demo2：I2C
- Demo3：ADC

第三阶段：显示与交互
- Demo4：SPI LCD
- Demo5：OLED

第四阶段：通信模块
- Demo6：ESP8266 / HC‑05
- Demo7：HC‑SR04
- Demo8：RFID

第五阶段：执行器
- Demo9：舵机
- Demo10：语音模块
- Demo11：风扇

最后阶段：整合
- Demo12：总工程合并

## 6. 实验记录建议
每个 demo 完成后，建议为其建立一个记录文件：
- `notes/demo01_result.md`
- `notes/demo02_result.md`
- ...

记录内容：
- 模块型号
- 引脚映射
- 测试时间
- 串口日志
- 结论：成功/失败/待优化
- 下一步要改动什么

## 7. 关键原则
- 不在一张面包板上堆太多模块
- 先验证总线协议，再验证业务功能
- 先验证低功耗与稳定，再考虑更复杂功能
- 先做单模块 demo，后整合工程
